# Building real projects

This is the Software & AI division's working library. It exists to get you from "I've never opened a terminal" to "I've contributed to a real project" — in that order.

No account, no sign-in. Browse the folder tree on the left, or work through the sections below from the top.

## Start here

Read these in order. Each one assumes the previous one, and the last one uses all of them at once.

**The toolchain**

1. **[Terminal Basics](/tutorials/terminal-basics)** — moving around, running commands, reading errors
2. **[Virtual Environments](/tutorials/virtual-environments)** — why your project needs its own isolated set of dependencies
3. **[Package Managers](/tutorials/package-managers)** — installing, pinning, and reproducing dependencies

**Using it**

4. **[Version Control](/tutorials/version-control)** — history, branches, and collaborating through pull requests
5. **[Your First Project](/tutorials/first-project)** — clone a real project, run it, change it, ship it

## Why this order

Most tutorials start with a language. We don't, because the language is rarely what breaks.

What breaks is `command not found`. What breaks is a package installed globally that silently upgrades and takes a different project down with it. What breaks is "it worked on my laptop" — because the dependency versions were never written down.

Those are all toolchain problems. They are boring, they are unglamorous, and they are the difference between a project you can hand to someone else and a project only you can run.

Version control comes fourth for the same reason. It's a tool, not a topic — and it's most useful once you have something worth keeping a history of.

## What comes after

A language. Once you can run code, install dependencies, and undo your mistakes, learning Python or TypeScript is comparatively straightforward — and much less frustrating, because the errors you'll hit are about the language rather than your environment.

After that: calling APIs, working with data, and eventually building AI-powered features.

That material is being written. If a topic you need isn't here yet, the [first project section](/tutorials/first-project/ship-it) shows you how to add it yourself.
